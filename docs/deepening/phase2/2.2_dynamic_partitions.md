# Phase 2.2 完成归档 — 分区动态生成

## 变更摘要
将固定的 `DailyPartitionsDefinition` 替换为 `DynamicPartitionsDefinition`，交易日分区键从 `trade_calendar.json` 动态生成，非交易日自动跳过。

## 核心变更

### 1. 分区定义重构 (`quant/orchestrator/dagster_assets.py`)
- **移除**: `DailyPartitionsDefinition(start_date="2020-01-01", end_offset=0)`
- **新增**: `DynamicPartitionsDefinition(name="trading_day")`
- **新增**: `_get_trading_day_partitions()` 从 `get_trading_days()` 动态获取交易日
- **新增**: `_init_trading_day_partitions()` 初始化函数（预留 Dagster API 注册入口）

### 2. 分区键来源
- **数据源**: `quant/execution/calendar.py` 的 `get_trading_days()`
- **数据来源**: `quant/data/trade_calendar.json` (akshare 获取 + 本地缓存)
- **覆盖范围**: 2020-01-01 至今天+60天，含 2025-2026 已知节假日

### 3. 兼容性
- 周度分区 `weekly_partitions` 保持 `WeeklyPartitionsDefinition` 不变
- Asset 依赖 `AssetIn("asset_name")` 语法完全兼容
- Dagster UI 可直接查看动态分区键

## 代码变更
- 文件: `quant/orchestrator/dagster_assets.py`
- 新增: `DynamicPartitionsDefinition(name="trading_day")`
- 新增: `_get_trading_day_partitions()` / `_init_trading_day_partitions()`
- 移除: `DailyPartitionsDefinition` 及相关 import

## 验证
- 语法检查: ✅
- 全量测试: 561 passed
- Dagster Definitions 加载: ✅ (15 Assets, 2 Jobs, 2 Schedules, 1 Sensor, 4 Resources)

## 注意事项
- 生产部署时需通过 `dagster instance partitions add` 注册动态分区键
- `dagster-daemon` 会自动管理分区生命周期
- 历史回填: `dagster asset materialize -a quant --partition 2020-01-02`
