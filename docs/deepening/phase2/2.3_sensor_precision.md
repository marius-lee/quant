# Phase 2.3 完成归档 — Sensor 精确控制

## 变更摘要
重构 `monitor_sensor`，基于 `quant.execution.calendar` 的精确交易时段判断 (`get_trading_period()` / `is_market_open()`)，实现盘中风控守护进程的精确生命周期管理。

## 核心改进

### 1. 交易时段感知
| 时段 | 行为 | 触发条件 |
|------|------|----------|
| **盘前** (09:25-09:30) | 启动守护进程 | `get_trading_period() == "盘前"` 且 `time >= 09:25` |
| **上午交易** (09:30-11:30) | 健康检查 | `get_trading_period() == "上午交易"` |
| **午休** (11:30-13:00) | 暂停检查 | `get_trading_period() == "午休"` |
| **下午交易** (13:00-15:00) | 健康检查 | `get_trading_period() == "下午交易"` |
| **盘后** (15:00+) | 停止触发 | `get_trading_period() in ("盘后", "休市")` |
| **休市日** | 不触发 | `not is_trading_day(today)` |

### 2. 精度提升
- **检查间隔**: 60秒 → **30秒** (`minimum_interval_seconds=30`)
- **启动时机**: 开盘前 5 分钟 (09:25) 预启动
- **午休处理**: 自动暂停，避免无效检查
- **精确停止**: 15:00 精确停止触发

### 3. 标签增强
```python
tags={"trigger": "market_open", "period": "盘前"}  # 启动时
tags={"trigger": "health_check", "period": "上午交易"}  # 盘中检查
```
