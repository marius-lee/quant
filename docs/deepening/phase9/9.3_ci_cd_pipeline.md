# Phase 9.3 完成归档 — CI/CD 流水线

## 变更摘要
构建完整的 CI/CD 流水线：代码质量检测、多阶段测试、Docker 多架构构建、安全扫描、Helm 验证、自动/手动部署、蓝绿发布、回滚支持。

---

## 核心产出

### 1. 主流水线 (`.github/workflows/ci.yml`)

| 阶段 | Job | 触发条件 | 关键步骤 |
|------|-----|----------|----------|
| **Lint** | `lint` | Push/PR | Ruff (lint/format) + MyPy (type check) |
| **Test** | `test` | Push/PR | PostgreSQL/Redis 服务、pytest 并行、覆盖率上传 |
| **Build** | `build` | Lint+Test 通过 | Docker Buildx 多架构 (amd64/arm64)、GHCR 推送、层缓存 |
| **Security** | `security-scan` | Build 完成 | Trivy 漏洞扫描 (CRITICAL/HIGH 阻断)、SBOM 生成 (SPDX) |
| **Helm** | `helm-lint` | Push/PR | `helm lint`、模板渲染验证 (dev/prod) |
| **Deploy Staging** | `deploy-staging` | Push to develop | Helm 部署到 Staging、冒烟测试 |
| **Deploy Prod** | `deploy-production` | Tag push (v*) | 蓝绿部署、健康检查、流量切换、通知 |

**并行度**: Lint/Test/Build 并行 → Security/Helm 并行 → Deploy 串行

### 2. 手动部署流水线 (`.github/workflows/deploy.yml`)

```yaml
# 支持操作
action: deploy | rollback
environment: staging | production
version: latest | v1.2.3 | sha-xxx
rollback-revision: 5  # 仅 rollback 时必填
```

**特性**：
- 环境级保护 (Environment Protection Rules)
- 手动确认生产部署
- 一键回滚到指定 Helm revision
- Slack 通知

### 3. Docker 多架构构建

```yaml
# docker/build-push-action@v5
platforms: linux/amd64,linux/arm64
cache-from: type=gha
cache-to: type=gha,mode=max
tags: |
  type=ref,event=branch
  type=semver,pattern={{version}}
  type=sha,prefix=
  type=raw,value=latest,enable={{is_default_branch}}
```

**优势**：
- 单一镜像清单支持多架构
- GitHub Actions 缓存加速构建
- 语义化版本标签自动生成

### 4. 安全扫描集成

| 工具 | 用途 | 阈值 |
|------|------|------|
| **Trivy** | 容器镜像漏洞扫描 | CRITICAL/HIGH = 阻断 |
| **Syft** | SBOM 生成 (SPDX-JSON) | 制品上传 |
| **CodeQL** | 代码静态分析 | 可选启用 |

```yaml
# Trivy 结果上传到 GitHub Security
- uses: github/codeql-action/upload-sarif@v2
  with:
    sarif_file: 'trivy-results.sarif'
```

### 5. Helm Chart CI 验证

```bash
# 依赖更新
helm dependency update helm/quant

# Lint 检查
helm lint helm/quant

# 模板渲染验证 (不安装)
helm template quant-dev helm/quant -f helm/quant/values/values-dev.yaml
helm template quant helm/quant -f helm/quant/values/values-prod.yaml
```

### 6. 部署策略

#### Staging: 滚动更新
```bash
helm upgrade --install quant-staging helm/quant \
  -f values-dev.yaml \
  --namespace quant-staging \
  --set quant.image.tag=<sha> \
  --wait --timeout 10m
```

#### Production: 蓝绿部署
```bash
# 1. 部署新版本到 green namespace
helm upgrade --install quant-green helm/quant \
  -f values-prod.yaml \
  --namespace quant-green \
  --set quant.image.tag=<version> \
  --wait --timeout 15m

# 2. 健康检查通过后切换 Ingress
kubectl patch ingress quant -n quant-prod \
  -p '{"spec":{"rules":[{"host":"quant.example.com",...}]}}'

# 3. 观察期后可回滚
# kubectl patch ingress ... quant-api
```

### 7. 环境变量与密钥管理

| 密钥 | 用途 | 存储位置 |
|------|------|----------|
| `KUBECONFIG_STAGING` | Staging 集群访问 | GitHub Secrets |
| `KUBECONFIG_PROD` | Production 集群访问 | GitHub Secrets (受保护) |
| `SLACK_WEBHOOK_URL` | 部署通知 | GitHub Secrets |
| `GITHUB_TOKEN` | GHCR 推送 | 自动提供 |
| `POSTGRES_PASSWORD` | 数据库密码 | 外部 Secret Manager / Sealed Secrets |

  ├── develop (持续部署到 Staging)
