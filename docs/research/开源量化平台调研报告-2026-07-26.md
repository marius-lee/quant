# 开源量化软件调研报告：直接可用的成熟方案

**调研日期**: 2026-07-26 | **范围**: 12个全球主流开源量化平台 | **焦点**: A股适用性 + 与当前自研系统对比

---

## 一、核心结论：自研这条路走错了吗？

**没有走错，但可以大幅缩减自研范围。**

当前自研系统覆盖了：数据同步、因子计算、IC评估、Alpha合成、风控、组合优化、执行模拟、Web仪表盘、调度器 — 这是**一个完整的量化平台底座**。

但业界没有一个平台能"开箱即用"地覆盖你全部需求。每个平台都有自己的侧重：

- 有的侧重**实盘交易**（vnpy/WonderTrader）
- 有的侧重**因子研究**（Qlib/VectorBT）
- 有的侧重**回测引擎**（Backtrader/Zipline）
- 有的侧重**AI模型**（Qlib/RD-Agent）

**最佳策略**: 保留自研核心（策略逻辑+因子体系+风控规则），**换掉底层轮子**（回测引擎、实盘执行、数据存储）。

## 四、推荐方案：三条路径

### 路径A：激进换底（推荐指数 ⭐⭐⭐⭐⭐）

**保留**: 策略逻辑、因子设计思路、风控规则、¥5000→¥100万目标
**换掉**: 全部基础设施

```
策略层 (保留)         基础设施层 (替换)
─────────────        ─────────────────
量化策略逻辑    →      vnpy 4.4 执行引擎
因子设计思路    →      vnpy.alpha (Alpha 101/158)
风控规则        →      vnpy 风控模块
信号生成        →      Qlib ML模型训练
组合优化        →      Qlib 组合优化
回测验证        →      NautilusTrader 回测
```

**优势**: 
- 10天可实现A股实盘闭环
- vnpy已有XTP/奇点/TORA等国内券商接口
- Qlib的ML模型比手写IC加权强一个量级

**劣势**: 
- 需要学习新框架
- 部分定制逻辑需适配

### 路径B：渐进替换（推荐指数 ⭐⭐⭐⭐）

**保留**: 因子体系、Alpha模型、风控层
**替换**: 回测引擎 + 执行引擎

```
保留: factor/ alpha/ risk/ optimizer/
替换: backtest/ → NautilusTrader 或 Backtrader
      execution/ → vnpy XTP接口
      data/ → vnpy数据服务 + Qlib DataLoader
```

**优势**:
- 最小改动，核心策略逻辑不受影响
- 回测准确性大幅提升
- 实盘对接一步到位

### 路径C：全盘保留，对标增强（推荐指数 ⭐⭐⭐）

**不替换任何模块**，只引入Qlib的因子库和ML模型作为Alpha模型的增强输入。

```
当前 pipeline:
  compute_all_factors → AlphaModel.combine → PortfolioConstructor

增强后:
  compute_all_factors (保留)  +  Qlib Alpha158 因子  +  Qlib LightGBM 预测
                                    ↓
                         AlphaModel.combine (增强)
                                    ↓
                         PortfolioConstructor (保留)
```

## 五、如果今天重新开始，最佳技术栈

| 层级 | 推荐 | 理由 |
|------|------|------|
| **数据** | vnpy数据服务 + tushare | 国内最稳定的A股数据管道 |
| **因子** | Qlib Alpha158 + 自研特有因子(涨跌停/LHB) | 通用因子用现成，特有因子自己写 |
| **Alpha** | Qlib LightGBM + 自研sleeve分仓 | ML预测收益 + 保留分仓逻辑 |
| **风控** | 自研(当前risk/已很好) | 行业中性化+Ledoit-Wolf+ATR止损已是业界标准 |
| **组合优化** | Qlib 嵌套优化 / 自研资本自适应 | 当前三层自适应设计很合理 |
| **回测** | NautilusTrader | 事件驱动纳秒精度，回测=实盘，零代码改动 |
| **执行** | vnpy 4.4 XTP接口 | 国内券商实盘对接最成熟方案 |
| **监控** | 自研web/(当前已很好) | Flask+SSE仪表盘够用 |
| **调度** | vnpy事件引擎 | 比自研orchestrator更稳定 |

## 六、最重要的结论

**自研这条路没有错。** 你两个月建立的因子体系、风控规则、资本自适应优化器、ATR止损止盈 — 这些都是**有壁垒的策略IP**，是任何开源平台都不会内置的。

但以下模块**不应该自研**：
1. 回测引擎 — 业界有更好的(NautilusTrader)，事件驱动比你的日频walk-forward精确两个量级
2. 实盘执行对接 — vnpy已经对接了国内20+券商，自研相当于重新发明轮子
3. 通用因子库 — Qlib的Alpha158/360覆盖了你70个因子中的大部分，且持续更新

**建议**：走路径B，用NautilusTrader换回测引擎，用vnpy换执行层，保留你的因子+风控+优化器。这两个月不是白费的 — 策略IP才是真正的价值。
